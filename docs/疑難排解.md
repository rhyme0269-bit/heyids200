# 疑難排解

指令請在專案資料夾中執行。若以下方法都無法解決，請把**完整的錯誤訊息**貼到 GitHub Issue，我們會協助處理。

---

## 建置時出現 `Failed to type check`

先看錯誤訊息中的檔案路徑。**如果路徑裡的資料夾名稱重複**，例如：

```
./heyids200/heyids200/src/app/layout.tsx
```

表示專案資料夾裡面還有**另一份專案副本**。請確認該資料夾內沒有需要保留的東西後刪除它。

若路徑正常，請執行 `git pull origin main` 取得最新版本後再試。

---

## 網站打不開（設定網域後）

依序確認：

**1. DNS 是否生效**

```bash
nslookup 您的網域
```

沒有顯示 IP，表示 DNS 尚未設定或尚未生效（最長可能數小時）。請對照 [網域設定](網域設定.md) 步驟 2。

**2. GitHub 的發布分支是否正確**

Settings → Pages → Source 的分支必須是 **`gh-pages`**，不是 `main`。

這是最常見的原因：選成 `main` 會發布程式原始碼而不是網頁。

**3. 舊網址也打不開？**

設定自訂網域後，原本的 `github.io` 網址會自動轉向新網域。因此**在 DNS 生效前，新舊網址都會連不上**，這是正常現象，設定完成後就會恢復。

---

## 發布了但網站沒更新

1. 確認發布指令最後顯示「**已發布**」。若顯示失敗，訊息中會說明原因（通常是尚未登入 GitHub）
2. 等 1～2 分鐘，GitHub 需要時間處理
3. 按 `Ctrl + F5`（Mac 為 `Cmd + Shift + R`）強制重新載入，排除瀏覽器快取
4. 確認 Settings → Pages 的分支是 `gh-pages`

---

## 後台改了但前台沒變

- 前台需**重新整理**才會看到更新
- 若是**線上網站**沒變，記得後台編輯只存在您的電腦，需要執行 `npm run publish` 才會上線

---

## 忘記後台密碼

密碼在專案的 `.env` 檔案中（`ADMIN_PASSWORD`）。

若修改 `.env` 後仍無法登入，是因為帳號在首次啟動時就已建立。請聯繫我們協助重設。

---

## 建置中斷、沒有明確錯誤訊息

若訊息中出現 `137` 或 `Killed`，是 Docker 記憶體不足。

請開啟 Docker Desktop → Settings → Resources，把 Memory 調高到 **4 GB 以上**，再重新執行。

---

## 想回到前一個版本

```bash
git log --oneline -10
```

找到要回復的版本編號後：

```bash
git checkout 版本編號
docker compose up -d --build
```

回到最新版本：

```bash
git checkout main
docker compose up -d --build
```

> 這只會切換程式版本，**不影響您在後台編輯的內容**。
