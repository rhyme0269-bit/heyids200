# 其他部署方案

> **一般不需要閱讀這份文件。**
>
> 本專案目前採用「在自己電腦編輯 → 發布靜態網頁」的方式，不需要租用主機，設定方式見 [README](../README.md)。
>
> 這份文件說明另一種選擇：把**含後台的完整網站**放上主機，讓後台可以從任何地方連線使用。

---

## 什麼情況需要改用主機

目前的方式有兩個限制：

- 後台只能在**那一台電腦**上使用
- 每次改完內容要**執行一次發布**，不是即時生效

若日後出現以下需求，可改用主機（程式不需要改寫）：

- 希望**多人同時**編輯內容
- 希望**不必開電腦**，用手機或任何地方都能登入後台

---

## 選主機的條件

含後台的完整網站**不是純靜態網頁**。後台編輯的文字與圖片存在資料庫檔案中，因此主機必須滿足兩個條件：

- 能**長時間執行伺服器程式**（不是每次請求才啟動）
- 有**永久保存的硬碟空間**（資料不會在重新部署後被清空）

---

## ⚠️ 這兩個平台不能用

| 平台 | 原因 |
|---|---|
| **Vercel、Netlify** | Next.js 網站最常被推薦的平台，但硬碟是暫時的。**後台編輯的內容與上傳的圖片會在每次更新後消失**。網站表面上看起來正常，等發現資料不見時已經來不及 |
| **GitHub Pages** | 只能放靜態頁面。本專案正是用它放正式網站，但後台是在您的電腦上執行 |

---

## 建議方案

| 方案 | 適合情況 | 月費參考 | 說明 |
|---|---|---|---|
| **VPS 虛擬主機 + Docker**（推薦） | 費用低、日後好轉移 | 約 200–400 元 | 國內：中華電信 HiCloud、遠振<br>國外：DigitalOcean、Linode、Vultr、Hetzner、AWS Lightsail |
| **容器平台** | 不想維護伺服器 | 約 200–800 元 | Render、Railway、Fly.io。**務必選有「持久化磁碟 / Volume」的方案**，否則資料會遺失 |
| 事務所自己的電腦 | 不建議 | — | 需固定 IP、24 小時開機。停電或網路中斷網站就離線 |

**建議規格**：1～2 GB 記憶體、20 GB 硬碟，這個網站很輕量。作業系統選 Ubuntu，安裝 Docker 後步驟與 README 的「首次安裝」相同。

> AWS EC2、Google Compute Engine、Azure VM 技術上可行，但計費複雜、管理介面繁瑣，對這種規模是過度配置。若要用 AWS，選 Lightsail 即可，它就是計價單純的 VPS。

---

## 免費方案可以用嗎

各平台都有免費額度，但大多不適合：

| 平台 | 免費內容 | 問題 |
|---|---|---|
| **Render 免費方案** | 免費主機 | **不含持久化磁碟**，資料會消失。與 Vercel 是同一種失敗方式 |
| **Oracle Cloud** | Always Free，額度最大 | 熱門區域常配不到機器；閒置帳號有被回收的案例，屆時網站與資料一併消失 |
| **Google Cloud** | 一台小主機永久免費 | 永久免費機型只在美國，台灣連線明顯變慢 |
| **AWS、DigitalOcean** | 新戶抵用金（約 2–3 個月） | 期限到即開始計費 |

> 免費方案條款變動頻繁，實際內容請以各平台官網為準。

**比較務實的省錢方式**：用新戶抵用金（DigitalOcean 約 60 天、Google Cloud 約 90 天）先跑幾個月，觀察實際使用量後再決定，並記得在到期前處理。

## 主機上的網域與 HTTPS 設定

若改用主機，網域設定方式與 GitHub Pages 不同。

### 1. 把網域指向伺服器

在網域商後台新增兩筆 **A 記錄**，值填您的伺服器 IP：

| 類型 | 名稱 | 值 |
|---|---|---|
| A | `@` | 伺服器 IP |
| A | `www` | 伺服器 IP |

### 2. 修改設定

編輯 `.env`：

```env
HTTP_PORT=80
HTTPS_PORT=443
DOMAIN=example.com.tw
NEXT_PUBLIC_SITE_URL=https://example.com.tw
```

### 3. 重新建置

```bash
docker compose up -d --build
```

> ⚠️ **一定要加 `--build`**。網址是在建置時寫入程式的，只用 `restart` 或 `up -d` 不會生效，網站對外宣告的網址（例如給 Google 看的 sitemap）會停留在舊值。

### 4. 啟用 HTTPS

在伺服器上申請免費憑證：

```bash
sudo apt install certbot
docker compose down                # 讓出 80 埠
sudo certbot certonly --standalone -d example.com.tw -d www.example.com.tw
```

把憑證複製到專案中：

```bash
mkdir -p nginx/ssl
sudo cp /etc/letsencrypt/live/example.com.tw/fullchain.pem nginx/ssl/
sudo cp /etc/letsencrypt/live/example.com.tw/privkey.pem nginx/ssl/
```

取消兩個檔案中的註解：

**`docker-compose.yml`** — nginx 的 volumes 底下：

```yaml
      - ./nginx/ssl:/etc/nginx/ssl:ro
```

**`nginx/nginx.conf`**：

```nginx
    listen 443 ssl;
    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    if ($scheme != "https") {
        return 301 https://$host$request_uri;
    }
```

重新啟動：

```bash
docker compose up -d --build
```

> **憑證每 90 天到期**。到期前執行 `sudo certbot renew`，重新複製上面兩個 `.pem` 檔，再 `docker compose restart nginx`。建議設定行事曆提醒或請工程師設定自動更新。
>
> 這是與 GitHub Pages 的主要差異之一 —— GitHub Pages 的憑證會自動更新，不需處理。

## 資料備份（主機版）

改用主機後，資料同樣存在專案的 `data/` 資料夾，備份方式見 [資料備份](資料備份.md)，只是需要在伺服器上執行。
